# 設計

## 構成

```text
CLI → aircon → echonet → UDP / LAN
       利用アプリ → echonet
```

| パッケージ | 責務 |
|---|---|
| `cmd/echonet` | 起動・終了シグナル |
| `internal/cli` | 引数、対話式初期設定、複数機器への並行操作、出力 |
| `internal/config` | YAML の検証・保存、対象・グループ展開と重複排除 |
| `aircon` | エアコンの型付き操作、定数・値変換 |
| `echonet` | 公開オブジェクト API、電文処理、UDP、要求管理、ローカルノード応答 |

CLI のコマンド・フラグ定義とシェル補完は Cobra を使う。補完ではローカル設定の読み取りと NIC 列挙のみを行い、機器通信や設定保存は行わない。
各コマンドを個別に定義し、操作値の検証・型変換は設定読み込みより先に行う。取得・設定は検証済みの操作を共通の対象解決・並行実行処理へ渡し、探索は専用の実行経路を使う。共通フラグ・補完の登録は共有する。

公開 API は [ライブラリ](library.md)、設定仕様は [CLI と設定](cli.md) にまとめる。
Go の構造体の合成で共通機能を共有し、高レイヤーから同じ Client を利用する。

## 通信

`echonet` のファイル名は、第2部の EOJ・TID・ESV に対応する概念で整理する。ファイル分割自体は本実装の構成であり、規格が定めるものではない。

| ファイル | 対応する規格の概念 | 実装の責務 |
|---|---|---|
| `object.go` | ECHONET オブジェクト（EOJ、3.2.4節） | オブジェクトに対する Get・SetC、入力検証、応答待ち |
| `transaction.go` | Transaction ID（TID、3.2.2節） | TID による要求の管理、登録・送信・解除 |
| `service.go` | ECHONET Lite サービス（ESV、3.2.5節） | 受信電文の ESV に応じた振り分け、要求に対応する応答の照合 |
| `property_map.go` | プロパティマップ（EPC 0x9D・0x9E・0x9F） | 状態変化アナウンス・Set・Get のプロパティマップの取得と解析 |

`discovery.go` はノード探索とインスタンスリストの解析、`client.go` は Client の生成・終了と共有状態を担当する。同期状態は一つの Client が所有する。TID の要求・応答間の対応付けは規格に従うが、同時要求数の上限や完了後の TID 隔離期間は本実装の方針とする。

- 一 Client が UDP 3610のソケットを所有する。NIC 未指定のユニキャストは OS の経路選択を使い、明示指定時だけ NIC を固定する。
- 探索先は `224.0.23.0:3610`。NIC 未指定時は探索開始時に候補を選び、マルチキャスト参加・起動通知を行う。候補が複数なら指定を必要とする。
- Get・SetC を公開し、複数 EPC を一電文で扱う。長さ・個数を検証し、暗黙分割しない。
- 応答は相手 IP・TID・SEOJ/DEOJ・ESV・EPC で照合する。使用中の TID を再利用せず、完了後も一定期間隔離する。
- 要求の TID・SEOJ は Client が管理し、DEOJ は Object の EOJ から決める。
- 通常要求は送信待ち・送信・応答待ちを通じて既定3秒を上限とする。探索は送信から結果収集までを timeout の対象とする。共有ソケットの送信は直列化し、要求ごとの期限・キャンセルを他の送信から分離する。
- 送信エラーはそのまま返し、送信成功後の設定応答未確認は設定結果不明とする。ローカル応答と起動通知の送信にも timeout を適用する。
- 待機時間は既定3秒。設定要求は再送せず、送信後の応答未確認を「設定結果不明」とする。
- 探索はノードの D6 を読み、IP・EOJ で重複を除く。IP を永続的な個体識別子とは扱わない。
- ローカルにはノードプロファイルとコントローラを公開する。受信通知の INFC に確認応答するが、通知購読 API は提供しない。
- `local.go` は、宛先 EOJ の解決、サービスごとの要求検証、応答電文の組み立て、送信を分ける。応答の組み立ては通信を行わず、要求とローカルプロパティを書き換えない。ESV の名前付き定数は第2部3.2.5節の表3-9〜3-11に対応させる。

## 設定と失敗時の扱い

CLI の初期設定は `setup.go` が進行を管理する。NIC 列挙は `interfaces.go`、対話入力と NIC 選択は `prompt.go`、探索と登録候補の抽出・重複排除・整列は `setup_discovery.go` に分ける。

設定処理は CLI 内部に閉じ、保存された interface は探索にのみ使う。初期設定は完了後に保存し、既存ファイルの置き換えには `--force` を必要とする。
新規設定は書き込み・同期・クローズ済みの一時ファイルをハードリンクで公開し、既存ファイルを上書きしない。同時作成でも成功するのは一つだけとする。既存設定の置き換え・対象切り替えは一時ファイルから行い、権限を保持する。対象切り替えでは YAML のコメントも保持する。
未対応・取得失敗・設定結果不明を区別し、欠損値を0などで補完しない。
設定の成功応答は要求受理の確認であり、物理動作の完了や複数設定の原子性を保証しない。

## 複数機器の操作

グループは個別 target のみ参照し、展開後の IP・EOJ で重複排除する。`target_selection.go` が対象の解決・全件検証と出力形式の判定を行い、`runAirconOperation` はその完了後に通信を開始する。
一つの Client を共有し、最大8操作のワーカーで各エアコンに並行して要求する。
結果は対象ごとに保持し、一台の失敗で他の操作を中断しない。全結果を待って指定順に出力する。
グループは CLI 設定の概念とし、公開ライブラリ API は変更しない。
