# 設計

## 構成

```text
CLI → aircon → echonet → UDP / LAN
       利用アプリ → echonet
```

| パッケージ | 責務 |
|---|---|
| `cmd/echonet` | 起動・終了シグナル |
| `internal/cli` | 引数、対話式初期設定、複数機器への並行操作、出力 |
| `internal/config` | YAML の検証・保存、対象・グループ展開と重複排除 |
| `aircon` | エアコンの型付き操作、定数・値変換 |
| `echonet` | 公開オブジェクト API、電文処理、UDP、要求管理、ローカルノード応答 |

公開 API は [ライブラリ](library.md)、設定仕様は [CLI と設定](cli.md) にまとめる。
Go の構造体の合成で共通機能を共有し、高レイヤーから同じ Client を利用する。

## 通信

- 一 Client が UDP 3610のソケットを所有する。NIC 未指定のユニキャストは OS の経路選択を使い、明示指定時だけ NIC を固定する。
- 探索先は `224.0.23.0:3610`。NIC 未指定時は探索開始時に候補を選び、マルチキャスト参加・起動通知を行う。候補が複数なら指定を必要とする。
- Get・SetC を公開し、複数 EPC を一電文で扱う。長さ・個数を検証し、暗黙分割しない。
- 応答は相手 IP・TID・SEOJ/DEOJ・ESV・EPC で照合する。使用中の TID を再利用せず、完了後も一定期間隔離する。
- 要求の TID・SEOJ は Client が管理し、DEOJ は Object の EOJ から決める。
- 待機時間は既定3秒。設定要求は再送せず、送信後の応答未確認を「設定結果不明」とする。
- 探索はノードの D6 を読み、IP・EOJ で重複を除く。IP を永続的な個体識別子とは扱わない。
- ローカルにはノードプロファイルとコントローラを公開する。受信通知の INFC に確認応答するが、通知購読 API は提供しない。

## 設定と失敗時の扱い

設定処理は CLI 内部に閉じ、保存された interface は探索にのみ使う。初期設定は完了後に保存し、既存ファイルの置き換えには `--force` を必要とする。
既存設定の置き換え・対象切り替えは一時ファイルから行い、権限を保持する。対象切り替えでは YAML のコメントも保持する。
未対応・取得失敗・設定結果不明を区別し、欠損値を0などで補完しない。
設定の成功応答は要求受理の確認であり、物理動作の完了や複数設定の原子性を保証しない。

## 複数機器の操作

グループは個別 target のみ参照し、展開後の IP・EOJ で重複排除する。全対象を通信前に検証する。
一つの Client を共有し、最大8操作のワーカーで各エアコンに並行して要求する。
結果は対象ごとに保持し、一台の失敗で他の操作を中断しない。全結果を待って指定順に出力する。
グループは CLI 設定の概念とし、公開ライブラリ API は変更しない。
