# CI/CD

## CI

PR・main への push・手動実行で GitHub Actions の CI を実行する。

- Go 1.25 系と最新安定版で、gofmt・モジュールファイル整合性・race detector 付きテスト・CLI ビルドと起動を確認する。
- golangci-lint は v2.15.0 に固定する。
- Linux のループバック以外の実機探索・操作は行わない。
- Actions はコミット SHA に固定し、通常のジョブは読み取り権限のみ使う。

Go の最低対応バージョンを変更するときは、go.mod とワークフローの `1.25.x` を併せて更新する。

## リリース

CI/CD の PR を main にマージした後、新しいバージョンタグを push すると自動リリースする。
タグは `v0.0.4` のような正式版の形式とし、main に含まれるコミットを指す必要がある。

```sh
# バージョンは例。公開する番号に置き換える。
git tag -a v0.0.4 -m "Release v0.0.4"
git push origin refs/tags/v0.0.4
```

タグの検証と CI が成功した後、Linux amd64・arm64 の `.tar.gz` と `checksums.txt` を GitHub Release に公開する。
アーカイブには CLI・LICENSE・README・設定サンプルを含める。追加のシークレットは不要で、公開ジョブのみ `contents: write` を使う。
成果物を添付したドラフトを作成し、完了後に公開する。途中失敗でドラフトが残った場合は、内容を確認して削除してから公開ジョブを再実行する。
既存タグへの付け替え・既存リリースへの上書きはしない。パッチ更新は末尾のみを一つ上げる。

既存タグのリリースは遡って作成しない。ワークフローの追加自体ではタグ作成・リリース公開は行わない。
