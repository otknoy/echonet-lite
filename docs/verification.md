# 検証と制限

## 開発コマンド

```sh
go test -race ./...
golangci-lint run -v
go build -o /tmp/echonet ./cmd/echonet
go install ./cmd/echonet
```

テストは仮想機器と Linux のループバック UDP を使用し、実機を自動で探索・操作しない。
ソケット作成が禁止された環境や3610使用中の場合、ループバック試験はスキップされる。
キャッシュ先に書き込めない場合は、実行環境の書き込み可能な一時ディレクトリを指定する。

## 主な検証対象

- 電文の生成・解析、不正長、SetGet の二群構造、プロパティマップの二形式。
- 応答照合、部分不可応答、設定結果不明、並行要求、TID の循環・隔離、キャンセル・Close。
- NIC 未指定のユニキャスト、探索後も OS に経路を任せること、明示指定時の送受信 NIC 固定。
- エアコンの値変換、未対応項目、CLI の引数・JSON・終了コード。
- YAML の読み込み・上書き優先順位・対象切り替え、コメントと権限の保持。
- 対話式 init の NIC 選択、登録可否・命名・対象選択、`--force`、中断・保存失敗時の元ファイル保持。

## 実機確認

1. エアコンの ECHONET Lite 機能を有効にし、同一 LAN の Linux で UDP 3610を利用可能にする。
2. `echonet config init` で探索・登録し、`echonet aircon status --format json` をリモコン表示と比較する。
3. 電源・モード・温度を一つずつ変更し、status で再取得する。試験後は元の状態に戻す。
4. メーカー・型番・ファームウェア・操作結果を記録する。

この開発環境では実機試験と実 UDP 通信は未検証。ループバック試験はソケット作成禁止でスキップされた。

## 対応範囲・制限

- Linux・IPv4・UDP のみ。同一ホストで3610を使用する別アプリとの同時利用は不可。
- 高レイヤーは家庭用エアコンの状態取得と電源・モード・設定温度の操作のみ。
- IPv6、TCP、Wi-SUN/Bルート、通知購読、風量・風向、タイマー、メーカー固有仕様は未対応。
- 85インスタンス以上のノードは D6 に含まれた範囲のみ探索する。
- 送信は1,472バイトまで。分割・再送をせず、経路 MTU は保証しない。
- ローカル識別番号は起動ごとに生成する。メーカコードは試作用の `FFFFFF` で、製品用の識別情報・認証対応は別途必要。
