# 検証・実機確認

## 自動テスト

- 既知電文、SetGet の二群構造、不正長、プロパティマップの二形式。
- 仮想通信での取得・設定・再取得、応答照合、部分不可応答、設定結果不明。
- 同時要求、TID の循環・隔離、キャンセル、Close、受信エラー。
- エアコンの値変換、未対応と部分失敗、CLI の引数・JSON・終了コード。
- YAML の読み込み・対象切り替え・引数の優先、コメントと権限の保持、保存失敗時の元ファイル保持。
- 対話式 init の NIC 選択、機器の登録・除外・命名、current_target 選択、入力中断・探索失敗。
- Linux のループバック UDP。ソケット禁止環境や3610使用中の場合のみスキップ。

## 実機確認手順

1. エアコンの ECHONET Lite 機能を有効にし、同一 LAN の Linux から UDP 3610を利用できる状態にする。
2. `aircon discover --interface NIC` で IP・EOJ を確認する。
3. `aircon status --host IP --eoj EOJ --interface NIC --format json` を実行し、リモコン表示と比較する。
4. 利用者が変更可能な状態で、電源・モード・温度を一つずつ変更し、status で再取得する。
5. 試験前の状態に戻し、メーカー・型番・ファームウェア・各操作結果を記録する。

自動テストから実機の探索・操作は行わない。実機試験は未実施。

今回の環境では `go test -race ./...` と `go vet ./...` が成功。UDP ループバック試験はソケット作成禁止のためスキップされ、実 UDP 通信は未検証。Git メタデータを取得できないため、CLI のビルドには `-buildvcs=false` を指定する。

## 試作の制限

- Linux / IPv4 / UDP のみ。同じホストで3610を使用するアプリとの同時利用は不可。
- Get・SetC を公開。通知購読、Wi-SUN/Bルート、メーカー固有仕様は未対応。
- 探索は D6 の一覧取得を使用。85インスタンス以上のノードは返された範囲のみ取得する。
- 機器の不正な応答順序や、規格外のプロパティマップには合わせない。
- 送信電文は1,472バイトまで。分割・再送はしない。経路 MTU は保証しない。
- ローカルノードはノードプロファイルとコントローラを公開。識別番号は起動ごとに生成し、メーカコードは試作用の `FFFFFF` とする。製品向けの識別情報・認証対応は別途必要。
- Status は一時点の読み出し。設定応答は受理の確認であり、物理動作の完了を保証しない。
